## Documentation Style

- Keep examples concrete and runnable.
- For a config-driven feature, document the data/JSON shape the code expects,
  not just the flag or option name.
- For subtle behavior, document the behavior and ordering, not only the surface
  (flags, options, signatures).
- Use relative links in Markdown. Never commit absolute filesystem paths.
